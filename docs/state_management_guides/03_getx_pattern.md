## 1. Why the GetX Pattern

GetX bundles three things: **state** (`.obs` + `Obx`), **dependency injection**
(`Get.put` / `Get.lazyPut` / `Get.find` organized in **Bindings**), and **routing**
(`GetMaterialApp` + `GetPage`). The architecture that fits it best is the **GetX Pattern**,
the structure generated by the official `get_cli`. It is **module-first**: each screen is a
module with its own binding, controller and view.

```text
 lib/app/
 ├── modules/number_trivia/            ← one folder per screen
 │     bindings/   NumberTriviaBinding ──registers──┐
 │     controllers/ NumberTriviaController (.obs) ◀─┤  uses
 │     views/      NumberTriviaView (GetView + Obx)  │
 │     widgets/                                      ▼
 ├── data/                                NumberTriviaRepository
 │     repositories/ ───────────────────▶   ├─ NumberTriviaRemoteProvider (http)
 │     providers/   (data sources)          ├─ NumberTriviaLocalProvider (prefs)
 │     models/                              └─ NetworkInfo
 ├── routes/   AppPages: route ↔ view ↔ binding
 ├── bindings/ InitialBinding: app-wide singletons (http, prefs, network)
 └── core/     errors, values (strings), utils, network, constants
```

| Decision | Why |
|---|---|
| **Bindings for DI** | A route's binding runs when the route opens and its objects are deleted when it closes. You get no leaks and no manual `dispose` calls. |
| **Controller owns the `TextEditingController`** | The view can be a `StatelessWidget` (`GetView`). `onClose()` disposes it. |
| **Separate observables** (`status`, `trivia`, `errorMessage`) | The usual GetX style. `Obx` rebuilds only for values it reads. |
| **`enum TriviaStatus`** | One clear source of truth for which of the 4 screens to show. |
| **No use cases, no Either** | GetX Pattern has data → controller → view. The repository throws typed exceptions; the controller maps them to messages. |
| **"providers" = data sources** | In GetX Pattern, `data/providers/` means API/storage classes. It has nothing to do with the Provider/Riverpod packages. |
| **`http` + `shared_preferences`** (not `GetConnect`/`get_storage`) | They are easy to mock and fake in tests, and they keep the data layer the same as in the other two guides, so the comparison is fair. |
| **Constructor injection inside classes** | Only bindings call `Get.find`. Every class takes its dependencies in its constructor, which keeps them unit-testable with plain mocks. |

**Packages**

| Package | Role |
|---|---|
| `get` **4.7.x** | State, DI, routing. (5.x is still a release candidate; this guide uses stable 4.x.) |
| `http` | API (+ `http/testing.dart` fake server) |
| `shared_preferences` | Cache |
| `internet_connection_checker_plus` | Real internet check |
| `mocktail` (dev) | Mocks without code generation |
| `integration_test` (dev, SDK) | Run the real app in tests |

### GetX in 60 seconds (words used below)

| Term | Meaning |
|---|---|
| `x.obs` / `Rxn<T>()` | Make a value observable (`Rxn` = can be `null`). Read/write with `.value`. |
| `Obx(() => …)` | Rebuilds when any observable **read inside it** changes. |
| `GetxController` | Holds state and logic. `onInit` / `onClose` are its lifecycle hooks. |
| `Get.put(obj)` | Register an object now. `Get.lazyPut(() => obj)` registers it and creates it on first `Get.find`. |
| `Get.find<T>()` | Get a registered object. |
| `Bindings` | A class whose `dependencies()` registers what a route needs. |
| `GetView<T>` | A `StatelessWidget` with a `controller` getter (`Get.find<T>()`). |
| `ever(rx, callback)` | A *worker*: runs `callback` on every change of `rx`. Used in tests to record changes. |
| `Get.reset()` | Delete everything registered. Use it in test `tearDown`. |

### How to work through this guide (the TDD rhythm)

Every step follows the same loop:

1. 📄 **Write the file** (production code).
2. 🧪 **Write its test** right away, if the file has logic.
3. ▶️ **Run only that test** with the command given.
4. ✅ **Check you get the expected number of passing tests.** Then go to the next step.

Files with no logic (pure data classes, interfaces, constants, barrel exports) have no
test of their own. Each one says why, and says which later test covers it.

> 💡 **Want strict TDD?** In every step, type the test file first, run it, and watch it
> fail (red). Then type the production file and run it again (green). The order of steps
> stays the same.

**Test words used in this guide**

| Word | Meaning |
|---|---|
| **Arrange / Act / Assert** | Prepare the mocks → call the code → check the result. Every test follows these three parts. |
| **Mock** (`mocktail`) | A fake object whose answers you choose: `when(() => mock.x()).thenAnswer(...)`. You check calls with `verify(...)`. |
| **`registerFallbackValue`** | mocktail needs one example value of a custom type before you can write `any()` for that type. |
| **Unit test** | Tests one class with its dependencies mocked. Fast and runs anywhere. |
| **Widget test** | Builds one widget in a fake screen (`testWidgets`, `tester.pumpWidget`). No device needed. |
| **Integration test** | Runs the whole app on a real device, simulator or desktop (`integration_test/`). |

### Step 4 — Input converter

Returns `null` for invalid input, which is the simplest contract of the three guides. The
controller turns `null` into the "Invalid Input" message.

📄 **Create:** `trivia_getx/lib/app/core/utils/input_converter.dart`

```dart
/// Converts the text typed by the user into a number >= 0.
///
/// Returns `null` when the text is not a valid unsigned integer.
int? stringToUnsignedInteger(String input) {
  final integer = int.tryParse(input.trim());
  if (integer == null || integer < 0) {
    return null;
  }
  return integer;
}
```

### Step 7 — Model: NumberTriviaModel

The only model, used everywhere (GetX Pattern has no separate domain entity). `==` and
`hashCode` are written by hand, so `expect` can compare two models.

📄 **Create:** `trivia_getx/lib/app/data/models/number_trivia_model.dart`

```dart
/// The only model of the app. GetX Pattern has no separate domain layer:
/// views, controllers and repositories all use this class.
class NumberTriviaModel {
  const NumberTriviaModel({required this.text, required this.number});

  factory NumberTriviaModel.fromJson(Map<String, dynamic> json) {
    return NumberTriviaModel(
      text: json['text'] as String,
      // The API can send 1 or 1.0, so read it as `num` and convert.
      number: (json['number'] as num).toInt(),
    );
  }

  final String text;
  final int number;

  Map<String, dynamic> toJson() => {'text': text, 'number': number};

  @override
  bool operator ==(Object other) {
    return identical(this, other) ||
        other is NumberTriviaModel &&
            other.text == text &&
            other.number == number;
  }

  @override
  int get hashCode => Object.hash(text, number);

  @override
  String toString() => 'NumberTriviaModel(number: $number, text: $text)';
}
```

### Step 8 — Remote provider (http data source)

📄 **Create:** `trivia_getx/lib/app/data/providers/number_trivia_remote_provider.dart`

```dart
import 'dart:convert';

import 'package:http/http.dart' as http;

import '../../core/constants/api_constants.dart';
import '../../core/errors/exceptions.dart';
import '../models/number_trivia_model.dart';

/// In GetX Pattern, a "provider" is a data source (API, storage...).
/// It has nothing to do with the Riverpod/Provider packages.
class NumberTriviaRemoteProvider {
  const NumberTriviaRemoteProvider({required this.client});

  final http.Client client;

  /// Throws a [ServerException] for every error.
  Future<NumberTriviaModel> getConcreteNumberTrivia(int number) =>
      _getTriviaFromUrl(ApiConstants.concreteTriviaUrl(number));

  /// Throws a [ServerException] for every error.
  Future<NumberTriviaModel> getRandomNumberTrivia() =>
      _getTriviaFromUrl(ApiConstants.randomTriviaUrl);

  Future<NumberTriviaModel> _getTriviaFromUrl(String url) async {
    final http.Response response;
    try {
      response = await client.get(
        Uri.parse(url),
        headers: const {'Content-Type': 'application/json'},
      );
    } on http.ClientException {
      throw ServerException();
    }

    if (response.statusCode != 200) {
      throw ServerException();
    }
    return NumberTriviaModel.fromJson(
      json.decode(response.body) as Map<String, dynamic>,
    );
  }
}
```

import 'dart:convert';

import 'package:shared_preferences/shared_preferences.dart';

import '../../core/errors/exceptions.dart';
import '../models/number_trivia_model.dart';

const cachedNumberTriviaKey = 'CACHED_NUMBER_TRIVIA';

class NumberTriviaLocalProvider {
  const NumberTriviaLocalProvider({required this.sharedPreferences});

  final SharedPreferences sharedPreferences;

  /// Throws a [CacheException] if nothing is cached.
  Future<NumberTriviaModel> getLastNumberTrivia() async {
    final jsonString = sharedPreferences.getString(cachedNumberTriviaKey);
    if (jsonString == null) {
      throw CacheException();
    }
    return NumberTriviaModel.fromJson(
      json.decode(jsonString) as Map<String, dynamic>,
    );
  }

  Future<void> cacheNumberTrivia(NumberTriviaModel triviaToCache) async {
    await sharedPreferences.setString(
      cachedNumberTriviaKey,
      json.encode(triviaToCache.toJson()),
    );
  }
}

### Step 10 — Repository (online → API + cache, offline → cache)

📄 **Create:** `trivia_getx/lib/app/data/repositories/number_trivia_repository.dart`

```dart
import '../../core/network/network_info.dart';
import '../models/number_trivia_model.dart';
import '../providers/number_trivia_local_provider.dart';
import '../providers/number_trivia_remote_provider.dart';

/// Online: fetch from the API and cache the result.
/// Offline: return the last cached trivia.
///
/// Throws `ServerException` or `CacheException`; the controller catches them.
class NumberTriviaRepository {
  const NumberTriviaRepository({
    required this.remoteProvider,
    required this.localProvider,
    required this.networkInfo,
  });

  final NumberTriviaRemoteProvider remoteProvider;
  final NumberTriviaLocalProvider localProvider;
  final NetworkInfo networkInfo;

  Future<NumberTriviaModel> getConcreteNumberTrivia(int number) {
    return _getTrivia(() => remoteProvider.getConcreteNumberTrivia(number));
  }

  Future<NumberTriviaModel> getRandomNumberTrivia() {
    return _getTrivia(remoteProvider.getRandomNumberTrivia);
  }

  Future<NumberTriviaModel> _getTrivia(
    Future<NumberTriviaModel> Function() getConcreteOrRandom,
  ) async {
    if (await networkInfo.isConnected) {
      final remoteTrivia = await getConcreteOrRandom();
      await localProvider.cacheNumberTrivia(remoteTrivia);
      return remoteTrivia;
    }
    return localProvider.getLastNumberTrivia();
  }
}
```

### Step 11 — NumberTriviaController

The controller is created with **constructor injection** (`repository:`), and the binding
passes `Get.find()` to it. So a unit test can build it with
`NumberTriviaController(repository: mock)`, without registering anything in GetX.

📄 **Create:** `trivia_getx/lib/app/modules/number_trivia/controllers/number_trivia_controller.dart`

```dart
import 'package:flutter/widgets.dart';
import 'package:get/get.dart';

import '../../../core/errors/exceptions.dart';
import '../../../core/utils/input_converter.dart';
import '../../../core/values/app_strings.dart';
import '../../../data/models/number_trivia_model.dart';
import '../../../data/repositories/number_trivia_repository.dart';

enum TriviaStatus { empty, loading, loaded, error }

class NumberTriviaController extends GetxController {
  NumberTriviaController({required this.repository});

  final NumberTriviaRepository repository;

  /// In GetX the controller owns the TextEditingController, so the view can
  /// stay a StatelessWidget. It is disposed in [onClose].
  final inputController = TextEditingController();

  // `.obs` makes a value observable; `Obx` rebuilds when it changes.
  final status = TriviaStatus.empty.obs;
  final trivia = Rxn<NumberTriviaModel>();
  final errorMessage = ''.obs;

  /// Called by the Search button and the keyboard "done" key.
  Future<void> searchConcrete() {
    // Read the text before clearing the field.
    final input = inputController.text;
    inputController.clear();
    return getTriviaForConcreteNumber(input);
  }

  /// Called by the "Get random trivia" button.
  Future<void> searchRandom() {
    inputController.clear();
    return getTriviaForRandomNumber();
  }

  Future<void> getTriviaForConcreteNumber(String input) async {
    final number = stringToUnsignedInteger(input);
    if (number == null) {
      _showError(AppStrings.invalidInputFailure);
      return;
    }
    await _load(() => repository.getConcreteNumberTrivia(number));
  }

  Future<void> getTriviaForRandomNumber() {
    return _load(repository.getRandomNumberTrivia);
  }

  Future<void> _load(Future<NumberTriviaModel> Function() fetch) async {
    status.value = TriviaStatus.loading;
    try {
      // Set the data BEFORE the status, so the view never sees
      // `loaded` without a trivia.
      trivia.value = await fetch();
      status.value = TriviaStatus.loaded;
    } on ServerException {
      _showError(AppStrings.serverFailure);
    } on CacheException {
      _showError(AppStrings.cacheFailure);
    }
  }

  void _showError(String message) {
    errorMessage.value = message;
    status.value = TriviaStatus.error;
  }

  @override
  void onClose() {
    inputController.dispose();
    super.onClose();
  }
}
```

### Step 18 — Module binding

Registers the module's data classes and controller with `lazyPut`. GetX creates them when
the view first calls `Get.find`, and deletes them when the route is removed (this calls
`onClose`).

📄 **Create:** `trivia_getx/lib/app/modules/number_trivia/bindings/number_trivia_binding.dart`

import 'package:get/get.dart';

import '../../../data/providers/number_trivia_local_provider.dart';
import '../../../data/providers/number_trivia_remote_provider.dart';
import '../../../data/repositories/number_trivia_repository.dart';
import '../controllers/number_trivia_controller.dart';

/// Runs when the route opens. `lazyPut` creates each object the first time
/// `Get.find` asks for it. When the route closes, GetX deletes them and
/// calls the controller's `onClose`.
class NumberTriviaBinding extends Bindings {
  @override
  void dependencies() {
    Get.lazyPut(() => NumberTriviaRemoteProvider(client: Get.find()));
    Get.lazyPut(() => NumberTriviaLocalProvider(sharedPreferences: Get.find()));
    Get.lazyPut(
      () => NumberTriviaRepository(
        remoteProvider: Get.find(),
        localProvider: Get.find(),
        networkInfo: Get.find(),
      ),
    );
    Get.lazyPut(() => NumberTriviaController(repository: Get.find()));
  }
}

| A test sees the controller of a previous test | Add `tearDown(Get.reset)` |
| `A TextEditingController was used after being disposed` | Don't call `onClose()` yourself while a widget still uses the controller; let `Get.reset` do it after the test |
| `pumpAndSettle timed out` | A spinner is showing; use `pump()` |
